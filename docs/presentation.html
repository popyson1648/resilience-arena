Resilience Arena03
03デモ — 障害発生から復旧まで

不正なデプロイを、観測の突き合わせで特定して巻き戻す。

原因は 1 つのツールでは分からない。メトリクスの異常開始時刻 × デプロイ時刻 × ログの内容を関連付けたときに初めて「直前のデプロイが原因」と言える情報設計にしている。

Resilience Arena04
04AIエージェントとツールの構成

判断はモデルに、安全と判定はサーバーに。

復旧の成否は、モデルの発言ではなくシミュレーション環境の実状態で判定する。誤った対象へのロールバックは受理されず、検証を省略した実行は「復旧失敗」になる。

Resilience Arena05
05Google 技術を使う理由

3 つとも、置き換えの利かない役割がある。

Gemini

実行時のすべての判断を担う。次に使うツール、原因の推定、復旧操作の選択は毎回モデルが決めており、台本の再生ではない。flash の低レイテンシが 20 秒級のライブデモを成立させる。

Agent Development Kit

ツール実行・セッション・イベントストリームの管理を担う。before_tool_callback がモデルの外側で安全規則を強制し、イベント列がそのまま UI の「実行過程の可視化」になる。

Cloud Run

審査員が URL を開くだけで使える公開環境。単一サービスに UI・API・エージェントを同居させ、SSE ストリーミングで進行を配信する。サービスアカウント認証で秘密情報を持たない。
